# Pull Request Workflow

- **One PR per feature.** Always create a SEPARATE pull request for each new feature, fix, or change. Never bundle multiple unrelated features/fixes into a single PR.
- **Branch off the latest `main`.** Always create the feature branch from the most recent `main` (fetch first) so the PR diff is clean and conflict-free.
- **Keep PRs focused and small** so they are easy to review and merge independently.
- **Descriptive titles + bodies** (what changed, why, what was tested, any follow-ups).
- Never push directly to `main`; always go through a PR.
